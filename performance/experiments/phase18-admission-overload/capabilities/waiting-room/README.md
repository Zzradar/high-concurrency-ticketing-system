# Waiting Room capability batch (Phase18 still in progress)

These are additional capability tests, not OFF A/B performance samples and not production SLA evidence. The final source freeze, overload proof and after/ measurement are still outstanding.

Implemented: Redis-TIME atomic prequeue/FIFO state, one position/lease per authenticated user/event, bounded cleanup/release, read-only status Lua, independent heartbeat, namespace/version fencing, dedicated traffic_control client (2 connections; existing PG 4 and Redis 2+2 unchanged), bounded request workers and scheduler, PostgreSQL policy snapshots, durable initialization markers and atomic system reset audit. Migration014 is additive; no previous migration was edited.

The Redis schedule index is updated separately from event-local keys; all event Lua keys share a hashed event slot. Refresh repairs incomplete publication, and repeated scheduler ticks are idempotent under the release bucket. Runtime reset commits policy version, generation and SYSTEM audit together. Single-instance ADMIN writes invalidate the snapshot before acknowledgement. Multiple instances discover external policy changes within the configured 2-second refresh period; this is a bounded eventual-control projection, not a claim of cross-instance linearizable administration. PostgreSQL remains authoritative for inventory and DRAFT visibility.

The read-only authentication path is restricted to admission status/heartbeat and enforced availability. Cache hits check strict integer timestamps against the current time and do not renew session/cache TTL. Misses use bounded per-token singleflight. Stable cache TTL jitter is 240–300 seconds with the current config. Read-only revocation can lag within that cache window if invalidation is unavailable; inventory, ADMIN and financial requests retain strict PostgreSQL authentication. The actual HTTP test measures zero additional user_sessions SQL calls over 20 warm GETs and verifies logout cache deletion and strict inventory rejection after disabling an admitted user.

Reservation restores validated idempotent results before admission; internal Checkout formal/recovery calls bypass the public new-reservation gate. Checkout only gates create, added seats and SELECTING confirm. RESERVED/SUBMITTING recovery, empty/reducing seat replacement, abandonment and financial flows retain their prior paths. Tests prove an admitted Shadow namespace cannot become a formal qualification or read protected Availability/create new inventory; a legitimate fresh formal admission succeeds.

Validation: CTest 35/35; policy HTTP 7/7 including all 16 namespace transitions and rollback; migration fresh/upgrade 2/2; Redis Lua 6/6; admission HTTP 5/5; Phase17 Venue/Publish OFF 13/13; frozen baseline 7/7. Frontend was unchanged in this batch (previous 269/269 and real API build). Tests include real Redis stop/start, one-event runtime loss, exactly one SYSTEM reset audit, no lease extension from GET, actual inventory rejection/success and recovery during outage.

Closed local issues: LIMIT parameters needed explicit PostgreSQL integer casts for Drogon's binary int32 binding; the Redis DUMP fixture needed binary rather than UTF-8 comparison; runtime-loss testing needed to wait for the event's reset publication while rejecting ADMITTED during transition. These fixes did not relax the safety assertions or alter baseline/protocol files.

Still required before delivery: distributed request rate limits and metrics, complete independent Bulkheads/resource overload evidence, Layout cache validation, adaptive polling and waiting UI, full financial/crash/verifier regression and frozen-protocol A/B. Do not deploy this intermediate branch as a completed Phase18 release.
