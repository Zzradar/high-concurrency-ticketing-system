# Layout and polling capability gates (not official A/B)

Published layout uses a weak versioned SHA-256 ETag over length-framed immutable session/venue/creation/publication metadata. A PostgreSQL public-visibility lookup precedes every validation; DRAFT/missing sessions return private no-store 404 even for wildcard/forged cache state. A 304 performs no full-seat fetch, returns no body, and retains ETag, Vary and public max-age=60/stale-while-revalidate=15. Full 200 uses the existing seat service and unchanged body serialization/order/prices. No Redis layout body or process LRU was added. All other API responses default to private no-store unless an explicit cache policy exists.

Snapshot/changed Delta suggest 2000 ms, empty Delta 5000 ms, degraded Snapshot 10000 ms; hasMore is drained serially with zero ordinary delay. All six read/cache configuration fields have strict integer bounds. The frontend validates response timing/types before use, applies bounded exponential empty/error backoff and jitter, respects bounded Retry-After, and clears streaks on authoritative refresh. One shared request chain covers all Zones, routes and auth epochs. Native visibility stops new work, pending work drains, and stale responses cannot overwrite new state. Unmount cancels scheduled work and invalidates responses. No SSE or WebSocket was added.

Validation: CTest 36/36; HTTP 3/3, including five empty 304 with full-layout SQL delta zero, unchanged repeat-200 body hash, DRAFT/absent visibility, private dynamic responses and actual Redis-offline degraded hints; frontend Vitest 275/275 and VITE_USE_MOCK_API=false production build. The earlier delayed-focus duplicate Snapshot is closed; its records remain under diagnostics/poll-probe-v1.

The independent long-hidden.mjs probe imports the frozen browser environment without changing protocol/. It uses an existing dedicated capability database, not the clean final A/B run, and changes only its own observation durations to 10 s visible / 91 s hidden / 10 s restored. Edge/PW/hash/flags and genuine one-window/two-tab topology remain identical. Result: 6 successful requests, max in-flight 1, no hidden starts for 91007 ms, exactly one restoration Snapshot, first restoration request 24 ms after bringToFront. This proves three maximum 30-second polling cycles of silence. Official after/ must still be recollected with all eight unchanged frozen protocol files after final source freeze; these capability samples are excluded from A/B ratios and do not represent production SLA.

The proposal to reuse a read-authentication result through a request attribute was not executed: automatic approval review rejected its unverified authentication boundary. Availability with an own Checkout retains its additional existing strict-authentication call. This is a query-cost limitation, not a weakened authorization path. Stable admission status has its separately proven zero-auth-SQL path.
