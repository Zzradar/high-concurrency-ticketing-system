## 修复规则

旧 login 在 await 后无条件增加 revision 并写 currentUser，迟到 A 能恢复退出用户、覆盖 B；LoginView 也无条件导航、写错误和 loading。

身份操作只在开始或明确失效时单调递增。login 捕获自己的序号；后续 login、logout、clearAuth、当前登录页面取消/卸载均使旧操作失效。await 的成功、失败与 finally 都校验序号，旧操作返回 null，不发布身份、不改初始化或 loading。LoginView 另校验页面存活、当前提交对象和同一序号，阻止旧导航与旧错误覆盖；取消旧页面不会使新的 B 失效。refreshMe 的完成分支同样受身份序号保护。

真实 HTTP login/logout 串行完成，失效登录收到 Set-Cookie 后在同一队列段清理，之后才允许 B 请求发出；me 等待该队列稳定。这样除了全局状态正确，还防止迟到响应覆盖浏览器 Cookie。取消信号用于失效当前操作，最终正确性由序号和 Cookie 变更排序保证。匿名清理的 401 保留本次登录原始凭据错误；login/logout 的 401 不再触发无所属操作的全局身份清空。
