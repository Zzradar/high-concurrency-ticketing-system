# Phase14 文件描述符修复与核心续测

本轮只将 SUT（被测服务器）后端进程的 nofile（打开文件描述符限额）从软限额 1024、硬限额 524288 改为 65535/65535。Compose（多容器配置）运行文件由原配置加仅包含 backend 服务 nofile 的覆盖配置生成，每次恢复、创建和重启均使用同一生成路径。正式测量完成后将等价设置写回标准 Compose。

双机采样读取已验证后端容器主进程的宿主 PID（进程编号）所对应的 `/proc` 信息，记录打开数量、软硬限额、占比及容器启动时间。最近五秒后端日志中 EMFILE（文件描述符耗尽）、Too many open files 和 Acceptor（连接接收器）错误的时间点单独保存；重叠窗口通过时间点去重，不能简单累加。此证据先于后端指标 HTTP（超文本传输协议）查询完成而落盘，避免指标端点中断丢失 FD 证据。达到 85% 且连续三个采样点未恢复，或再次出现相关错误时停止负载。

本轮不重跑已经通过的初始化、故障夹具、G0（发生器能力校准）、完整 Smoke（冒烟测试）和全量自动化测试。增量资格明确引用原资格的路径、测量提交和 SHA-256（内容摘要），验证所有被引用原始证据摘要，并绑定本轮干净提交、目录树对象和三端基线。只允许经审计的 Phase14 FD 适配代码及文档、测试变化；正式负载、targets（目标参数）、数据、镜像和拓扑必须保持一致。记录类型为增量资格，不能伪装成新完整资格。新增与直接受影响的定向测试在 Windows 和 Linux 执行。

场景使用原 `phase14_core_plan.json` 的十项顺序与参数。按用户后续更正，从首次启动服务起预计六小时，预留二十五分钟核验、保存证据、停止专属服务和撤销临时密钥。用户进一步授权：若仅因正常执行较慢且未发生问题，可以延长完成剩余场景；延时不得绕过安全停止或无效重试上限。有效失败停止对应场景族升档，数据正确性或资源安全异常停止全部续测；不为更好结果重复已获得有效结果的场景。

旧报告及原始证据保持不变，新结果使用新运行编号。标准 Compose 写回后的提交不会追溯改变测量提交，最终报告同时记录测量提交和交付提交。
